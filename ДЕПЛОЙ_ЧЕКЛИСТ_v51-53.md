**Составил:** бизнес-аналитик · **Дата:** 02.08.2026
**Для:** разработчика (нужен `wrangler`-доступ к Cloudflare D1)

## Контекст

Код трёх фич залит и фронт `v=72` уже на GitHub Pages. Роуты воркера
раскатаны (проба `POST` → 401 = существуют). **Незакрыт один шаг: D1-миграции.**
Воркер до миграции деградирует молча (все чтения в `try/catch`), поэтому баг
не виден в логах — фичи просто не работают, включая **реальные платежи**.

Затронутые фичи:
- **v=51** — Монетизация №5 «пропуск кликера» (100⭐), колонка `has_click_bypass`
- **v=52** — Лидерборд престижа + `POST /prestige/confirm`, колонки
  `prestige_count` / `last_prestige_at` / `is_prestige_pioneer` + сид `config`
- **v=53** — Монетизация №6 per-апгрейд скип (20/40/60⭐), колонка
  `paid_unlocked_upgrades` + `star_invoices.upgrade_id`
- **v=44** (хвост) — Монетизация №4 «+10% навсегда», колонка
  `has_permanent_production_boost` (ранее не подтверждена — ТД-1)

## Шаг 2. Применить недостающие миграции

⚠️ ALTER **не идемпотентны** — ошибка «duplicate column» = уже применено, это ОК,
идём дальше.

```bash
# v=44 (бует №4)
wrangler d1 execute cookie-clicker-analytics --remote --command "ALTER TABLE users ADD COLUMN has_permanent_production_boost INTEGER NOT NULL DEFAULT 0"

# v=51 (бует №5)
wrangler d1 execute cookie-clicker-analytics --remote --command "ALTER TABLE users ADD COLUMN has_click_bypass INTEGER NOT NULL DEFAULT 0"

# v=52 (лидерборд престижа)
wrangler d1 execute cookie-clicker-analytics --remote --command "ALTER TABLE users ADD COLUMN prestige_count INTEGER NOT NULL DEFAULT 0"
wrangler d1 execute cookie-clicker-analytics --remote --command "ALTER TABLE users ADD COLUMN last_prestige_at INTEGER NOT NULL DEFAULT 0"
wrangler d1 execute cookie-clicker-analytics --remote --command "ALTER TABLE users ADD COLUMN is_prestige_pioneer INTEGER NOT NULL DEFAULT 0"

# v=53 (бует №6)
wrangler d1 execute cookie-clicker-analytics --remote --command "ALTER TABLE users ADD COLUMN paid_unlocked_upgrades TEXT NOT NULL DEFAULT ''"
wrangler d1 execute cookie-clicker-analytics --remote --command "ALTER TABLE star_invoices ADD COLUMN upgrade_id TEXT"

```

## Шаг 5. Прод-тест платёжных потоков (реальные Stars)

Через живой Telegram-клиент на `@bestcookieclickerbot`. После каждого — сверить,
что эффект применился и **повторный вебхук не задваивает** начисление.

- [ ] **№5** «Пропуск кликера» (100⭐) → флаг `has_click_bypass=1`, клик-апгрейды
      покупаемы без набора кликов; повторная покупка → 409 `already_owned`.
- [ ] **№6** per-апгрейд скип (20/40/60⭐) → `upgrade_id` попал в
      `paid_unlocked_upgrades`, апгрейд разлочен; повторная покупка того же → 409.
- [ ] **№4** «+10% навсегда» (200⭐) → флаг выставлен, кнопка «Куплено ✓»;
      повторный инвойс отклонён ДО оплаты (409).
- [ ] **Престиж**: вознесение в Telegram → `/prestige/confirm` инкрементит
      `prestige_count`; топ сортируется по престижу; частое повторное
      вознесение без активности → 429 (`too_soon`/`no_activity`).
- [ ] **Пионер**: первое вознесение → `is_prestige_pioneer=1`, бейдж «🚩 Пионер»
      в топе (пока `pioneer_granted < 50`).

Быстрая проверка счётчика пионеров:
```bash
wrangler d1 execute cookie-clicker-analytics --remote --command "SELECT value FROM config WHERE key='pioneer_granted'"
```

  совместимы, старый код их игнорирует.

  **уменьшать `?v=` не нужно** — просто вернётся старый файл.
